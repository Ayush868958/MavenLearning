1. What is Maven?
   Apache Maven is a build automation and dependency management tool
   commonly used in Java projects.
   It helps us: - Compile Java source code. - Run tests. - Package compiled
   code into JAR/WAR files. - Download and manage external libraries. -
   Keep a standard project structure.
   Maven uses a file named pom.xml to configure the project.
2. What is pom.xml?
   pom.xml means Project Object Model. It describes important
   information about the project and its build.
   Example:
   <groupId>com.ayush</groupId>
   <artifactId>MavenLearning</artifactId>
   <version>1.0-SNAPSHOT</version>
- groupId: identifies the project group or organization namespace.
- artifactId: the project's artifact/name.
- version: the current project version.
- properties: stores reusable build settings, such as Java
  source/target version.
- dependencies: lists external libraries required by the project.
3. Maven standard project structure
   MavenLearning/
   ├── pom.xml
   ├── src/
   │   ├── main/
   │   │   ├── java/       # Application source code
   │   │   └── resources/  # Application resources/configuration
   │   └── test/
   │       ├── java/       # Test source code
   │       └── resources/  # Files needed by tests
   └── target/             # Generated build output
   Important: - src/main/java contains application code. -
   src/test/java contains test code. - src/main/resources may contain
   configuration files and other resources. - target is generated by
   Maven; it can usually be regenerated by building again. - Do not
   normally commit generated target output to Git.
4. Maven build lifecycle
   A lifecycle is an ordered set of build phases. When a later phase is
   run, Maven runs the earlier phases in that lifecycle first.
   Common phases:
   Phase                               Purpose
   validate                          Checks that the project is
   configured correctly enough to
   proceed.
   compile                           Compiles main application source
   code.
   test                              Runs tests using the configured
   test framework.
   package                           Packages compiled code, often into
   a JAR or WAR.
   verify                            Runs checks to verify the
   package/build is acceptable.
   install                           Installs the project's built
   artifact into the local Maven
   repository so other local projects
   can use it.
   deploy                            Publishes the artifact to a remote
   repository when configured.
   Useful commands, run from the directory containing pom.xml:
   mvn validate
   mvn compile
   mvn test
   mvn package
   mvn verify
   mvn install
   Other useful command:
   mvn clean
   clean removes generated build output, usually the target directory.
   It belongs to Maven's separate clean lifecycle.
   package vs install
- mvn package creates the packaged artifact in the project's
  target directory.
- mvn install runs the required earlier phases and then copies the
  artifact into the local Maven repository (normally under the user's
  .m2/repository directory).
  install does not mean uploading the artifact to GitHub or to a
  remote repository. Remote publication is generally handled by deploy
  with appropriate configuration.
5. What is a dependency?
   A dependency is an external library that a project needs to use.
   For example, Apache Commons Lang provides utility classes such as
   StringUtils. Maven can download the library and make it available to
   the project.
   Example dependency:
   <dependencies>
   <dependency>
   <groupId>org.apache.commons</groupId>
   <artifactId>commons-lang3</artifactId>
   <version>3.21.0</version>
   </dependency>
   </dependencies>
   Add the <dependencies> section inside <project>, usually after
   <properties> and before </project>. Do not place it inside
   <properties>.
   Meaning of dependency coordinates: - groupId: publisher/group
   namespace. - artifactId: specific library. - version: the library
   version requested.
   Maven uses configured repositories---Maven Central is the usual default
   public repository---to resolve and download dependencies. You usually do
   not need to download the JAR manually.
   Using Commons Lang in Java
   package com.ayush;

import org.apache.commons.lang3.StringUtils;

public class Main {
public static void main(String[] args) {
System.out.println(StringUtils.capitalize("ayush"));
System.out.println(StringUtils.isBlank("   "));
}
}
Expected output:
Ayush
true
The library is optional: Java already has built-in methods for many
tasks. Use an external library when it provides useful functionality for
the project.
6. Dependency scopes
   A scope describes where a dependency is needed.
   Scope                               Beginner-level meaning
   compile                           Default scope. Available for
   compiling the main code and
   generally at runtime.
   test                              Used for compiling/running tests;
   not intended as a production
   runtime dependency.
   provided                          Expected to be supplied by the
   runtime environment; available for
   compilation and tests but normally
   not packaged as a runtime
   dependency.
   runtime                           Needed at runtime but not for
   compiling the main source code.
   Example: a test library such as JUnit is normally declared with test
   scope.
   <dependency>
   <groupId>org.junit.jupiter</groupId>
   <artifactId>junit-jupiter</artifactId>
   <version>YOUR_CHOSEN_VERSION</version>
   <scope>test</scope>
   </dependency>
   Use a real, compatible released version when adding this dependency; the
   placeholder above is explanatory and should not be pasted as-is.
7. Transitive dependencies
   A dependency may itself require other libraries. Those additional
   libraries are called transitive dependencies.
   Maven can resolve these automatically from dependency metadata, so we do
   not usually have to declare every supporting library manually. If two
   libraries require incompatible versions, dependency management may be
   needed.
8. What is a repository?
   A Maven repository is a location where artifacts (libraries, metadata,
   and versions) are stored.
- Local repository: stored on your computer, usually in
  C:\Users\<username>\.m2\repository on Windows.
- Remote repository: a server that Maven can download from or
  publish to, depending on configuration and permissions.
- Maven Central: a widely used public repository for Java
  libraries.
  Do not confuse: - Repository = where artifacts are stored. - Dependency
  = a library your project requires. - Maven = the tool that resolves
  dependencies and runs the build.
9. What is a JAR?
   JAR means Java Archive. It is a ZIP-based package format that can
   contain compiled .class files, resources, and metadata.
   After running:
   mvn package
   look inside target/ for the generated JAR, for example:
   target/MavenLearning-1.0-SNAPSHOT.jar
   Important: not every JAR is directly executable with java -jar. A
   runnable JAR needs suitable manifest information (including a main
   class) and may need its runtime dependencies packaged or otherwise
   available. A normal Maven JAR is not automatically a self-contained
   application.
10. What is Gradle, and how is it different?
    Gradle is another build automation tool. Both Maven and Gradle can
    compile code, run tests, manage dependencies, and build artifacts.
- Maven commonly uses pom.xml and XML.
- Gradle commonly uses build.gradle (Groovy DSL) or
  build.gradle.kts (Kotlin DSL).
  Maven dependency example:
  <dependency>
  <groupId>org.apache.commons</groupId>
  <artifactId>commons-lang3</artifactId>
  <version>3.21.0</version>
  </dependency>
  Gradle Groovy DSL example:
  dependencies {
  implementation 'org.apache.commons:commons-lang3:3.21.0'
  }
  The dependency is the same; the configuration syntax differs. Since this
  project already uses Maven, focus on Maven first.

13. Quick revision
- Maven is a build automation and dependency management tool.
- pom.xml configures the Maven project.
- mvn compile compiles main code.
- mvn test runs tests.
- mvn package creates a package such as a JAR.
- mvn install adds the built artifact to the local Maven repository.
- A dependency is a library the project uses.
- A repository stores artifacts.
- Dependency scopes control where a dependency is needed.
- target/ contains generated build output.
